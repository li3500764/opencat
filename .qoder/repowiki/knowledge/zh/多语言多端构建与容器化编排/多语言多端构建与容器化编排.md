## 构建系统总览
OpenCat 采用「pnpm workspace + Docker Compose」的多语言、多端统一构建方案：Next.js（Node/TypeScript）作为 Web 仪表盘，Go Worker 负责后台长任务，Tauri 2.0 提供桌面壳。所有服务通过 docker-compose 一键拉起 Postgres+Redis 依赖，生产环境使用独立编排文件。

## 核心工具链
- 包管理：pnpm（启用 corepack），使用 `pnpm-workspace.yaml` 聚合 Next.js 应用与共享库；`onlyBuiltDependencies` 仅对 Prisma 引擎执行原生构建。
- 运行时：Node 22 Alpine 镜像；Go 1.22；Rust/Tauri 2。
- 数据库 ORM：Prisma 7，连接 URL 从 `prisma.config.ts` 注入，schema 可安全公开。
- 容器化：Docker 多阶段构建 + docker-compose 编排。

## 关键文件与职责
- `package.json`：定义 dev/build/start/lint/db:generate 等脚本，`postinstall` 自动 prisma generate，`tauri:dev` / `tauri:build` 驱动桌面端。
- `next.config.ts`：根据环境变量切换输出模式——`TAURI=1` → `output: 'export'`（供 Tauri 静态加载），`STANDALONE=1` → `output: 'standalone'`（Docker 生产），否则标准 server 模式；同时外部化 `pg/@prisma/client/bcryptjs` 避免打包进前端。
- `Dockerfile`：四阶段构建（base → deps → builder → runner），以非 root 用户运行，健康检查指向 `/api/auth/session`。
- `worker/Dockerfile`：Go 静态编译（`CGO_ENABLED=0`，去除符号表），Alpine 运行镜像，设置中国时区。
- `src-tauri/Cargo.toml` & `tauri.conf.json`：Tauri 2 crate 配置，前端产物目录 `../out`，开发时 `beforeDevCommand: pnpm dev` 启动 Next.js 于 3001 端口。
- `docker-compose.yml`：开发环境，Postgres 17 (pgvector) 映射到本地 5433，Redis 7，命名卷持久化。
- `docker-compose.prod.yml`：生产编排，app/worker/postgres/redis 四个服务，内部网络隔离，挂载 `public/downloads` 与 `public/generated-images` 为共享存储。
- `prisma.config.ts`：Prisma 7 独立配置文件，从 `DATABASE_URL` 读取连接串，schema 路径固定到 `prisma/schema.prisma`。

## 架构与约定
- **输出模式三态**：
  - 本地开发：`pnpm dev` → Next.js 标准 server。
  - Tauri 桌面：`TAURI=1 pnpm build` → 静态导出至 `out/`，由 Tauri 直接加载。
  - Docker 生产：`STANDALONE=1 next build` → `.next/standalone`，最小镜像运行。
- **依赖服务解耦**：Postgres 与 Redis 始终通过容器网络暴露给 app/worker，本地开发用 5433 端口避开宿主 PG 占用。
- **Worker 无状态**：Go Worker 通过 Redis Stream 消费任务、PostgreSQL 持久化结果，支持水平扩展（`WORKER_CONCURRENCY` 控制并发）。
- **安全基线**：容器内非 root 用户、关闭 Telemetry、忽略 TS 构建错误避免部署阻塞。

## 开发者应遵循的规则
1. 新增 Node 依赖后重新生成 lock 并同步 `pnpm-workspace.yaml`；原生模块需加入 `onlyBuiltDependencies` 列表。
2. 修改 Prisma schema 后必须执行 `pnpm db:generate`（或 `pnpm postinstall` 自动触发）再生成客户端。
3. 在 Next.js 中引入 `pg`、`@prisma/client`、`bcryptjs` 等原生包时不要手动打包，保持 `serverExternalPackages` 默认值。
4. 需要静态导出的场景（如 Tauri）务必设置 `TAURI=1`，而非直接改 `next.config.ts` 的 output。
5. 生产部署前复制 `.env.production.example` 填写完整环境变量，并通过 `docker compose -f docker-compose.prod.yml up -d --build` 启动。
6. Go Worker 新增依赖后需在 `worker/Dockerfile` 中确认 GOPROXY 可用，静态编译参数 `-ldflags="-s -w"` 应保持开启以减小镜像体积。
