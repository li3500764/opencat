OpenCat 采用以环境变量为核心、配置文件为补充的分层配置策略，覆盖 Next.js 应用、Go Worker、Prisma 迁移脚本以及 Tauri 桌面壳四个运行面。

## 1. 配置来源与加载顺序
- 环境变量（最高优先级）：所有运行时敏感项通过 process.env / os.Getenv 注入，由 Docker Compose 的 env_file 或 environment 字段提供。
- .env 文件：开发阶段通过 dotenv.config() 显式加载，仅用于本地调试；.env* 已被 .gitignore 排除，禁止入库。
- 静态 JSON 配置：Tauri 桌面壳使用 src-tauri/tauri.conf.json 声明窗口尺寸、构建产物路径等不可变打包期配置。
- Prisma 独立配置：Prisma 7 将 DATABASE_URL 从 schema.prisma 剥离到 prisma.config.ts，并通过 dotenv 手动加载，使 schema 可安全公开。

## 2. 各组件配置入口
- Next.js 应用：next.config.ts，关键变量 TAURI=1（静态导出）、STANDALONE=1（Docker standalone 模式）
- Prisma Client：src/server/db/index.ts + prisma.config.ts，关键变量 DATABASE_URL（pg Pool 最大 10、空闲 30s 回收）
- Go Worker：worker/internal/config/config.go，关键变量 DATABASE_URL、REDIS_URL、ENCRYPTION_KEY、WORKER_CONCURRENCY、WORKER_TASK_TIMEOUT、LOG_LEVEL、DOWNLOADS_DIR（自动探测 ../public/downloads -> ./public/downloads）
- Tauri 桌面壳：src-tauri/tauri.conf.json，包含 productName、version、build.frontendDist、build.devUrl、窗口尺寸与安全策略
- 生产编排：docker-compose.prod.yml，统一挂载 .env.production，覆盖 DATABASE_URL、REDIS_URL 指向容器内部网络地址

## 3. 架构约定与设计决策
- 无集中配置中心：项目未引入统一配置服务（如 Consul/Vault），而是依赖操作系统级环境变量加 Docker Compose 的 env_file 实现跨进程共享。
- 默认值兜底：Go Worker 的 LoadConfig() 对每个键都提供合理默认值（并发 20、超时 1800s、日志 info），确保本地直接 go run 也能启动。
- 下载目录自动探测：Worker 在 DOWNLOADS_DIR 为空时按相对路径回退探测，兼顾源码根目录与容器 /app/public/downloads 两种部署形态。
- 构建期 vs 运行期分离：Next.js 通过 TAURI / STANDALONE 两个布尔开关切换 output: export | standalone，避免硬编码分支；Tauri 的 devUrl 与 frontendDist 分别对应开发热重载与打包产物。

## 4. 开发者应遵循的规则
1. 新增配置项一律走环境变量，并在 docker-compose.prod.yml 的 environment 段给出容器内覆盖值。
2. 敏感信息不入库：.env* 已在 .gitignore 中忽略，README 指引复制 .env.example 作为模板。
3. Prisma 迁移脚本需自行 dotenv.config() 后再读取 DATABASE_URL，不要依赖 Next.js 自动加载。
4. Go Worker 新增配置需在 worker/internal/config/config.go 的 Config 结构体与 LoadConfig() 中同步添加，并设置非空默认值。
5. Tauri 配置变更只改 tauri.conf.json，不要在运行时动态修改窗口尺寸等打包期参数。
